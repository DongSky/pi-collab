# 产物存储、保留与回收

项目「资源与费用 → 产物保留与回收」提供产物额度、保留策略、计量、保护原因、清理申请及结果。默认原生运行，Docker 使用相同策略与固定路径清理流程。

## 额度与范围

迁移 058 登记工作区、快照、验证副本、整合副本和仓库。工作区继续使用 057 的成员/项目额度；其余种类共享项目产物额度，默认 100 GiB。快照预留 512 MiB，验证及仓库按当前工作区额度预留，整合预留两个工作区额度加 512 MiB。验证/整合在执行中约每两秒计量，未知或超额会请求停止；快照在完成前计量。空闲产物由执行器轮转扫描，删除后才释放计量。

这是逻辑文件软配额。快速写入可能短暂超额，仓库导入后的注册/后续扫描不等于下载阶段硬限制。迁移 060 的动态预览副本已加入产物额度，按服务生命周期在退出确认后回收；Git broker 导出、静态预览、日志、数据库及容器镜像不在这个额度内；部署管理员仍需监控实例实际磁盘。

## 保留与引用

默认快照/副本至少保留 90 天、工作区归档后至少 7 天、项目审计至少 180 天。维护者启用 MFA 后可修改策略，带版本检查、原因、审计与幂等键。已固定的保留日期不因调低策略缩短；更长的当前策略继续保护已有数据。页面显示实际保护日期。

到期不会自动删除。维护者选择对象、填写原因、确认永久回收后，执行器重新检查权限版本、期限、计量与引用：

- 工作区须已归档、运行已结束，且无待处理/可用快照和 Git 引用；物理清理还必须验证原生进程或容器的退出凭据。
- 快照的成果、验证、恢复工作区、共编、代码讨论及预览引用均会阻止回收。
- 验证副本须已结束且退出证据完整，无成果/预览引用；证据和来源快照继续保留。
- 整合副本须无活动/未知执行，无修复任务、评审或推进引用。仓库基线持续保护。

历史引用采用保守规则：即使引用者已结束，也可能继续保留来源。没有「强制忽略引用」入口。依赖图自动压缩、整个项目销毁与全部实例文件清理属于独立的后续治理范围。

## 删除与恢复处理

清理队列持久化。执行器先将对象标记回收中，并撤销对应快照/整合的可用状态，再删除服务端计算的 UUID 目录；请求不能指定文件路径。执行器崩溃后可继续同一目标。失败显示「清理未完成，需要重试」，维护者可重新确认以重试固定目标；不会恢复已撤销的来源。排队后出现引用或权限变化则取消清理。

业务记录、验证证据、退出凭据和清理审计保留。回收前如需保存物理数据，应使用已有冷备份流程。运维排空会等待已排队/正在执行的清理结束；清理失败记录可随冷备份保留。

项目审计须另行明确确认，每批最多删除 1000 条超过期限的明细；新审计记录保留批次计数及 SHA-256 摘要。组织级审计不在此操作范围内。

## 验证

`tests/collab/artifacts.test.ts` 使用隔离 PostgreSQL、实际 Pi 工具进程和物理文件，覆盖额度、权限/MFA、真实快照与工作区回收、引用竞争取消、验证副本回收、失败重试、审计截止与幂等；同一测试可设置 `PI_COLLAB_TEST_DOCKER=1` 运行真实容器版本，无模型推理。

`PI_COLLAB_E2E_FOCUS=capacity npm run test:collab:identity:e2e` 覆盖双成员策略共享、角色/CSRF、失败快照残留的确认清理、审计清理和桌面/手机布局。浏览器使用独立数据库与代码副本。
