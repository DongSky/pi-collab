当前按用户最新要求优先补齐所有功能块的基础流程，执行顺序以 [功能骨架交付清单](foundation-delivery.zh-CN.md) 为准；本文件保留原始完整范围和详细验收标准。

版本：v0.2 · 2026-09-24 · 状态：功能基础已贯通，最终验收未完成；逐项进展与验收证据见 [实施状态](implementation-status.zh-CN.md)

## 新增阶段：功能验收后改造界面

用户于 2026-09-24 明确要求：全部功能验证与调试完成后，改成参考 Cursor 的现代多人协作工作台。执行要求和退出标准见 [界面改造清单](ui-modernization.zh-CN.md)。当前先继续功能验收，界面改造已授权但尚未开始；不得把未验收项标为完成以提前切换阶段。

## 当前范围与开发顺序

- **基础已接通**：M1 身份权限/执行、M2 多 AI 协调与独立子任务、M3 Git/讨论/证据/交接、M4 历史/配额/备份/本机生产安装。P2 的共编、OIDC、GitLab、接口兼容检查、预览和项目记忆也各有基础流程。逐块证据见 [功能骨架交付清单](foundation-delivery.zh-CN.md)。
- **验收未完成**：真实 GitHub/GitLab/企业 IdP、公网 HTTPS/SMTP、托管 Linux 发布作业、参考硬件长期容量/故障指标及真实团队 Beta 试点。已有本机协议测试、真实 Pi 与容器证据不能替代这些验收。
- **增强保留**：远端原生合并队列、多节点调度、SCIM、语言服务/AST 分析、跨版本评论映射、GitLab MR 行内评论、动态预览 WebSocket/长流式/应用 Cookie，以及更多环境工具链。它们不从原计划删除，也不标为已实现。
- **开发流程**：先检查新发现的基础缺口，若有则优先打通数据、权限、API、页面和主流程；基础齐备后再逐模块处理已复现问题，每项定向验证后收尾。外部环境验收按具体账户/主机另行执行，不反复扩充已通过模块的故障组合。

本清单配合 [产品与开发计划](development-plan.zh-CN.md)，可直接转换为 Issue。本机环境和调试路径见 [本地开发方案](local-development.zh-CN.md)。多用户各自指挥 AI 并行开发是首版核心；同一会话接管只是辅助体验。

估算单位为工程人日，含实现、相关测试、评审修改和说明文档；不等于日历天，不含单列的 QA/运维支持。首版 26 项合计 **192 工程人日**；关键不确定性预留约 17%（33 人日），合计约 225 人日。主计划中的 18–19 周考虑依赖、集成与缓冲，不能简单把各项全部并行。

负责人缩写：TL = 技术负责人/后端，RE = 运行与 Git 工程师，FE = 前端/协作工程师，QA = 测试/运维。每项指定一个主责，其他人可协作；下面的依赖为必要前置，具体 PR 可进一步拆分。

## M1：身份权限与执行基础（40 人日）

### M1-01 用户、邀请、会话与 MFA

- 主责：TL；估算：9 人日；依赖：P0-05。
- 交付：bootstrap、邀请、登录/退出、密码重置、管理员 MFA、设备会话撤销和本地 SMTP 测试环境。
- 验收：过期/重复邀请失败；重置使旧会话失效；Owner 不可全部删除；降权/禁用账户生效；浏览器 CSRF、限速与恢复码路径测试通过。

### M1-02 组织/项目权限与数据访问边界

- 主责：TL；估算：8 人日；依赖：M1-01、P0-02。
- 交付：领域 schema、统一授权、复合外键/RLS、审计 API、缓存隔离；所有旧敏感入口改造或禁用。
- 验收：两个组织、各两个项目互猜所有资源 ID 均不能越权；数据库连接池不遗留前一个请求的租户上下文；下载/搜索/导出也受控。

### M1-03 执行管理与工作区生命周期

- 主责：RE；估算：8 人日；依赖：P0-03/05、M1-02 接口契约。
- 交付：创建/停止/恢复/归档 workspace，独立 clone、原生持久目录及 scoped agentDir；可选容器增加受限挂载与资源上限。
- 验收：原生进程不继承个人 HOME/秘密环境；失联旧执行者仍可能存活时不复用可写目录；停止超时有明确状态；UI 不接受任意宿主路径。容器配置另验非 root、无宿主 HOME/Docker socket 挂载及资源上限。

### M1-04 可靠命令、事件与恢复

- 主责：RE；估算：7 人日；依赖：M1-02/03。
- 交付：命令 inbox/outbox、幂等键、工作区租约/epoch、SSE 游标与快照回退、运行对账。
- 验收：100 个重复启动请求只有一个有效 run；重启/网络中断不重复执行未知副作用；旧 epoch 回调被拒绝；断线能补业务状态。

### M1-05 用户、项目与执行状态界面

- 主责：FE；估算：8 人日；依赖：M1-01/02/04。
- 交付：登录与成员管理、项目选择、任务外壳、会话权限、运行状态和错误恢复 UI。
- 验收：权限不足有明确可理解反馈；隐藏按钮之外还有后端拒绝；用户看到自己的 AI 和其他获授权 AI 的真实状态。

#### M3-01 已实施流程与退出标准

1. **完整出站历史读取（已实现）**：从 SQL 固定的 ready 导出读取，先验 manifest hash 和 Git 对象；列出全部新增提交、提交说明、父关系和各版本变更，不只展示最终 diff。合并支线、中途新增后删除的文件、模式与二进制都必须可识别；不按请求传来的 SHA 或宿主路径任意读对象。读取前后检查当前项目权限；损坏导出、越权和展示超限有明确状态。
2. **浏览器预览与确认（已实现）**：登录/同源接口、完整历史/原始字节和刷新后同键重试已接入。迁移 028 保存与 manifest/observation hash、全部提交对象 hash/路径计数和确切目标绑定的成员声明；SQL 拒绝缺失/重复/替换版本。页面要求逐文件与逐提交核对、二进制/超限/排除范围说明及显式目标/披露确认。不同成员或预览共享全局仓库 ID + ref 占用，当前任务控制者可显式撤回未发送的确认，撤权后重授不恢复旧记录。窗口标记仍是本地状态，最终提交才持久化，且不证明软件能判断人实际理解内容。见 [ADR-040](adr/0040-browser-outgoing-history.md) 和 [ADR-041](adr/0041-durable-push-confirmations.md)。
3. **持久远端发送（原生已实现）**：单独的显式发送请求在读取写入凭据之前去重，不能自动消费已有确认；沿用已实现的完整确认、授权版本与全局目标占用。发送前替换未发送撤回规则，使可能开始的远端写入不能通过撤回释放。服务重新核验原导出与目标，最终事务记录精确发送字节 hash 和唯一发送意图后才能 receive-pack。拒绝默认/整合/受保护分支、过期确认、并发目的地和权限变化。
4. **未知远端结果（原生保留与封存已实现）**：区分 Git 效果与令牌清理；一旦可能开始发送，即使断连、取消、令牌撤销或暂时观察到旧 SHA，也继续保留目的地占用。核查只能记录可证实的结果，不能自动重放、改写历史或释放给下一次发送。用实际延迟远端写入、SQL/HTTP 回包丢失和服务 SIGKILL 验收；无法证明的状态仅允许具备 MFA 的组织管理员兼项目维护者明确封存；旧目标永久隔离，从新工作区继续。见 [ADR-042](adr/0042-durable-task-push-delivery.md)。
5. **接入交付（已实现）**：仅将已确认的远端任务 SHA 交给 M3-02 的 PR/CI/webhook；PR diff、检查、评审与最终保护分支合并使用同一版本。外部账户及安装委派/轮换验收单列，不能以回环 fixture 代替。
6. **后端对等（基础已实现）**：迁移 056 接通 Docker Git、交付、整合和修复，常驻执行器实际调度已验证；复用原生请求/确认/队列协议。原生仍为默认，不要求安装 Docker。完整异常组合和外部环境验收保留。
