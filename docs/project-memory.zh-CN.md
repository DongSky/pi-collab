# 可审核、可撤回的项目记忆

迁移 053 接通项目记忆的数据、任务页面、人工审核和 AI 协作工具。记忆类型包括设计决策、接口约定、失败经验及验证方法。

在任务页“项目协作记忆”中填写仓库、稳定标识、内容、来源依据和适用基线。默认只针对指定 SHA；维护者审核后也可批准适用该仓库所有基线的明确提案。每次修订是新的不可变版本和内容 hash，保留来源任务、来源运行、复制来源和父版本。不能原地改写已审核正文。

独立维护者批准后，记忆才会出现在适用运行的 `collab_get_context.projectMemory`。作者不能自批；普通开发者和 AI 不能审核或撤回。并发提案批准时比较当前父版本，一份获批后另一份必须重新提案。发布新版本使旧版被替代；撤回保留历史，从后续上下文读取中移除正文并返回近期撤回记录。

AI 使用 `collab_propose_memory` 提案，服务自动固定其实际运行、任务、仓库和基线。运行短期能力及当前权限持续检查，已退出运行不能继续提案。仓库文本和记忆内容不能授予执行权限、放宽审计、提高预算或自动运行保存的命令。AI 提案仍需人工独立审核。

“修订或恢复此内容”会复制旧文本形成新提案，记录复制来源，仍需重新批准；不会直接把旧版恢复为生效。历史内容、状态与审核理由可由项目成员查看。每仓库最多 32 项生效记忆，每项目最多 100 项待审提案，页面显示最近 200 项。

撤回无法从 AI 已读取的旧对话中删除文字。AI 在任务边界重新读取上下文；若必须立即停止使用某条信息，应停止当前运行并开启新运行。记忆是可追溯的项目上下文，并非权限或兼容性保证。

验证：2 项专项覆盖 AI 来源固定、幂等、权限、独立审核、版本筛选、撤回、并发父版本和重新审核恢复；9 项既有协作工具回归通过，包括真实 Pi 扩展注册与协议调用。双成员浏览器完成提案、批准、撤回、历史恢复提案与桌面/390px 检查，无外部模型推理。
