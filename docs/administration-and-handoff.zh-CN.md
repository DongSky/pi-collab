# 环境交接、账户恢复与管理

F6 原生基础范围，2026-09-24。组织管理页新增「运行与审计管理」，项目「资源与费用」新增环境配方，交接快照新增环境清单及重建入口。

## 环境配方与交接

维护者可发布不可变的环境配方。基础支持原生 Node 环境与 `npm ci --ignore-scripts --no-audit --no-fund`，使用新工作区的独立 HOME 和 npm 配置，不读取宿主机 npm 凭据。自动安装需要根目录 package.json/package-lock.json，不接受项目 .npmrc；需要执行安装生命周期脚本的包、Python/其他包管理器暂不自动安装。

新运行在提交时固定当时的配方。取得执行名额后，先在独立 Pi 进程的受管理工具中完成环境准备，再接收 AI 工作指令。安装超时/失败沿用原有退出、隔离和对账流程；不会在未知旧工作区继续安装。依赖下载是配方的显式行为，没有通过模型决定要不要跳过失败。

环境清单记录 Node 版本/二进制 hash、npm CLI hash、Pi CLI hash、平台/架构/内核、依赖声明与锁文件 hash、配方和准备结果。没有把数据库密码或宿主机环境变量写入交接记录。

打开快照「环境交接与重建」，核对原运行模型、配方、依赖和未捕获内容，点击「选择此交接环境，准备新运行」，再在运行表单确认模型与指令并启动。恢复创建全新工作区，沿用来源配方；项目后来发布的默认配方不覆盖它。执行器核对 Node/npm/Pi/平台/架构指纹，不一致会停止并报告，不能宣称恢复了原环境。内核版本记录用于核对，不自动还原操作系统。模型凭据和执行授权仍由当前成员、当前模型设置决定，不从历史记录恢复已撤销权限。

测试库和端口重新分配，依赖按恢复后的锁文件安装。测试数据库内容、外部服务状态、秘密、运行中的进程和 OS 包未快照；本页明确列出这些缺失项。Node 以外的锁文件只记录，不伪装为已自动构建。旧运行没有环境记录时也会明确提示。后续可在快照验证入口重跑既有固定命令，保留新的环境和退出证据。

## 组织审计与模型管理

组织管理员启用 MFA 后可检索操作名、操作者、项目名和资源，并向前翻页。没有对应项目成员资格时仅显示审计元信息，不显示操作详情。模型列表显示配置、版本、启用状态及本机凭据是否存在，绝不返回密钥或密文。模型操作仍要求项目维护者权限和 MFA。

停用模型或删除本机凭据会递增版本并撤销已有模型能力；网关据此终止/拒绝调用，未知请求仍保留费用。启用只供新的运行使用，不恢复旧能力。删除不销毁历史记录，不替代在提供商后台撤销旧 API key。

轮换使用部署管理员本机命令：

```sh
npm run model:rotate -- --profile PROFILE_UUID --actor ADMIN_EMAIL \
  --expected-version VERSION --reason '核验后轮换此项目模型凭据' \
  --credential-file /private/model-credential.json
```

文件应为当前用户拥有、权限 0600 的 JSON，字段为 apiKey、baseUrl。版本从管理页读取。轮换不自动启用原来停用的模型；旧模型能力失效，需要新建运行。命令不打印凭据，不向提供商发送推理请求。新模型仍使用原有 model:import 命令。

## 证据不足的异常运行

管理页集中列出本人有维护权限的待核查运行，可以再次请求进程退出证据核查，或填写原因登记隔离处置。隔离处置撤销模型能力、释放/撤回受管理测试资源申请，并保存审计。

登记处置不会把未知效果改成成功，不会声称旧进程已退出，不会解锁旧工作区或强制释放其并发/端口。需要真实退出证据才能按原有恢复流程结束隔离；管理员可基于已有安全快照另建工作继续调查。此入口提供可追溯处置，不提供绕过进程证明的「强制成功」。

## 全因子丢失恢复

用户同时丢失密码、验证器和恢复码时，由有数据库管理权限的本机部署管理员在线下核验身份。普通组织管理员不能在网页里给其他用户取消 MFA。

```sh
npm run account:recover -- --email USER_EMAIL \
  --reason '记录线下身份核验依据及恢复原因' \
  --output /private/account-recovery.txt --identity-verified
```

命令写入新建的 0600 文件，不在终端打印凭证。文件内包含 30 分钟有效的单次恢复链接；同一账户新签发会撤销旧凭证。由管理员私下交给经核验的本人，不自动发邮件。URL 凭证位于 fragment，恢复页读取后清除地址栏片段，不进入服务端 URL 日志。

用户提交新密码后，事务内消费凭证，删除旧验证器/恢复码、旧设备会话和相关认证验证记录，递增组织/项目授权版本，撤销模型能力并请求停止原账户运行。角色和成员启用状态保持不变；不会重新激活已停用账户的团队权限。恢复后重新登录，并重新设置 MFA 才能进行管理员敏感操作。

发行和消费都有审计，明确权力来源是本机部署管理员签发的凭证。正常 MFA 禁用保护仍然生效，恢复通路不是可设置的普通会话变量。该流程不是自动证明线下身份；核验责任由执行命令的部署管理员承担。

## 邮件配置

管理页显示 file/smtp/unconfigured 及必要配置是否存在。SMTP 使用原有 PI_COLLAB_MAIL_TRANSPORT、SMTP_URL、SMTP_FROM 部署变量，页面不显示密钥，不自动发测试邮件。“配置存在”不表示真实投递验收成功；公网邮件、Docker 与生产部署验收归 F7。

## 验证

管理/恢复专项覆盖组织与项目可见性、模型版本/删除/轮换、隔离状态保留及单次账户恢复。环境专项实际启动 Pi、安装本地依赖、产生快照、换人恢复、验证原配方与运行时不匹配拒绝；不调用外部模型。相关身份/恢复/执行/网关回归共 60 项通过。网页专项分别覆盖管理与账户恢复、环境交接，并检查桌面和 390px 布局。

主实例已升级 043–045 并重载原生服务。网页证据：test-results/collab/administration-{desktop,mobile}.png 与 environment-handoff-{desktop,mobile}.png。类型检查与 lint 通过。
