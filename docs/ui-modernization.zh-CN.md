# pi-collab 工作台界面改造

记录日期：2026-09-24。用户要求：全部功能验证与调试完成后，把界面改成参考 Cursor、适合多人协作的现代开发工作台。当前工作台改造已实现，最终生产包的原生／Docker 冒烟已通过；以下目标与实际验收记录分开记录。

## 执行顺序

1. 按 `module-closeout.zh-CN.md` 完成功能验收和问题修复，保留每项真实证据；页面未验收、外部环境未验收及未开发增强分别记录。不能为了进入改版阶段把剩余项改成通过。
2. 功能验收完成后实施下述工作台改造。若外部环境或原计划增强仍未完成，保持明确状态；不自行把“全部完成”的前提缩成协议测试通过。
3. 改版后重跑受影响功能流程，再用 Computer Use 检查桌面、窄屏、键盘和双账户协作。原生与 Docker 的角色、控制权、验证和交付规则继续由服务端执行。

当前本机功能收尾证据已归档，外部部署与计划增强继续单列。负责人转交已验收，不重复执行；UI 改造无需再次请求授权。

## 产品布局

参考 Cursor 的分区、紧凑密度、标签工作区和键盘操作，保留 pi-collab 品牌与多人开发信息。

- 左侧活动栏：项目、任务、代码、变更与评审、团队活动；图标带可访问名称和提示。
- 次级侧栏：当前团队／项目切换、可搜索任务列表、我的任务与团队任务、各任务运行状态；可折叠并调整宽度。
- 中央工作区：按任务打开标签，提供概览、代码／共编、变更／验证、讨论等视图。目标与验收使用足够宽度；避免把整个表单挤在当前 290px 侧栏。
- 右侧 AI 面板：当前任务的运行历史、流式消息、输入、模型与明确的控制者。可以切换关注其他成员 AI；旁观、申请接管、回答问题和停止的权限反馈清楚可见。
- 底部面板：终端、运行日志、验证结果、问题列表。可收起／调整高度，终端保持焦点与滚动位置。
- 项目级视图：任务依赖与 AI 全景、整合队列、团队活动、资源费用。组织／成员／部署等管理表单进入设置页，避免贯穿每个任务的一整页长表单。

成员颜色辅助识别同一成员的 AI、任务和共编光标，同时保留姓名与文字标签。只展示真实在线信号；组织成员列表不能冒充在线成员。

## 多人协作的主要交互

- 任意运行头部持续显示任务、发起人、当前控制者、模型、状态和连接状态。选中别人的任务不会改变指令发送目标。
- 等待输入、排队、依赖失效、范围重叠、验证失败、待独立评审分别使用明确文字；AI 输出完毕不能显示为代码已交付。
- 团队动态可跳到对应任务、讨论、成果或固定版本差异。切换标签不清空草稿、重复启动运行或重置控制申请。
- 对比两名成员的工作时可并列打开固定差异或任务；共享分支仍通过既有组合验证和评审流程推进。
- 成果交付区依次呈现快照、固定验证、成果、整合、独立评审、推进，并显示失效原因和下一可执行动作。
- 接管申请与通知集中呈现，操作前明确指出对象；危险／不可逆操作保持原有确认和审计。

## 视觉与可访问性

使用中性深灰背景和分层面板、细边框、统一图标与间距，减少大面积绿色、装饰卡片和空白。强调色只标记选中、主要行动及重要状态；错误和警告不能只靠颜色区分。正文、代码、时间和状态采用一致的字重与字号层级。

提供浅色主题与系统主题选项。布局偏好按浏览器用户保存，不改变团队设置。标准文本对比度至少 4.5:1，焦点清晰；缩放到 200% 后主要操作仍可达。响应式在宽度不足时切为单面板和抽屉，不压缩成不可读的多列。

命令面板支持任务／项目切换和常用导航。快捷键需显示、可通过键盘访问，避免在编辑器、终端和输入法组合期间抢占按键。动画遵循减少动态效果偏好。

## 实施拆分与功能保护

1. 梳理 `TeamShell`、`TaskRuns` 与设置页的入口清单，建立每个现有功能的新位置映射。
2. 建立设计变量和按钮、输入、标签、状态、面板、空态／错误／加载等基础组件。
3. 改造工作台骨架、导航、可调整面板与任务标签；先复用现有业务组件及权限判断。
4. 拆分任务运行长页面，把代码、协作、证据、交付和资源放到对应视图；保留持久请求编号和失败重试语义。
5. 统一初始化、登录、账户、组织和管理页。首次使用应能顺序完成建团队、MFA、项目、仓库、模型和成员邀请。
6. 完成键盘、响应式、跨标签草稿保护与实际双账户验收，再更新截图和用户说明。

懒加载和切换面板不得导致运行事件丢失、共编草稿销毁或重复订阅／请求。标签关闭不等于停止 AI。权限撤销后清除受保护内容，不能依赖隐藏按钮维护授权。

## 改版退出标准

- 全部旧入口有新位置，用户可从任务到达运行、共编、Git、验证、评审及交付；没有用装饰按钮代替功能。
- 双账户真实完成启动各自 AI、旁观、接管、问答、共编、讨论、独立评审和推进，保留错账户／旧版本拒绝路径。
- 刷新、断线、切任务／项目、关闭再打开标签均保持正确对象和草稿；终端与运行输出不会串到别人的任务。
- 至少检查 1440px、1280px、768px、390px，长中文任务名、长代码、空项目、大量任务、错误和加载状态。
- 关键路径可纯键盘操作；类型、lint、受影响测试及原生／Docker 相关回归通过。
- Computer Use 实际截图和操作结果通过后才能标记界面改造完成。

## 已核对的入口迁移清单（2026-09-25）

后续实现按以下映射检查，不删除已存在的业务组件：

- 活动栏／项目侧栏：项目切换、任务搜索／负责人筛选、创建任务、任务与 AI 全景、资源费用、历史；账户与组织链接继续指向现有受保护页面。
- 任务概览：目标、验收、前置依赖、`TaskEditor`、`Subtasks`、`ResolutionContext`、固定撤回来源。
- 代码与共编：`CollaborativeEditor`；冻结交接明确返回本任务 AI 表单，不能由文档级查询误选其他标签中的输入。
- Git 变更：`WorkspaceGit`、`TaskPushPreviews`、`GitHubRepositoryInfo`、`GitHubImports`、`GitHubSyncs`、`GitLabPanel`。
- 验证与交付：`TaskSnapshots`、`TaskValidations`、`TaskResults`、`ProjectIntegrations`。快照恢复只选定来源，不隐式启动。
- 讨论与协作：`TaskDiscussions`、`TaskNotes`、`TaskContracts`、`WorkIntents`、`ProjectMemory`。收件箱与控制面板的跳转必须同时选择正确任务及子视图。
- 预览与环境：`CheckpointPreviews`（含动态服务）、`ProjectResources`。
- 右侧 AI：原运行方式／仓库／模型／快照／提示词、运行历史、错误、停止／对账／归档、流式输出、`RunControl` 与问答；持续展示运行发起人与当前控制者。
- 底部终端：原 `SharedTerminal`，保留同一运行实例及单控制者判断；切换任务不会发送停止命令。

标签和分区切换应保留已打开组件的草稿状态；隐藏标签应停止 UI 订阅，重新显示时先获取当前授权与最新状态。刷新后的恢复须以账户／项目／任务为键，不能将旧控制权、运行已完成或原幂等请求当作可直接执行的授权。底层权限和版本检查保持服务端执行。

## 2026-09-25 实现与浏览器验收

已实现活动栏、项目与任务搜索、全部／我的筛选、可折叠侧栏、任务标签、七个任务分区、独立 AI 面板、底部共享终端、命令搜索、深浅／系统主题。侧栏及 AI 面板支持拖动和方向键调整宽度；标签按账户／项目保存，运行草稿与未确认请求按账户／项目／任务隔离。隐藏任务使用 React Activity 保留组件状态并暂停效果；再次显示重新读取授权与运行记录。
