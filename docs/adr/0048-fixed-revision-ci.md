# ADR-048：固定 PR 版本的 CI 规则与观察

- 状态：已实现；8 项专项及隔离双浏览器验收通过，迁移 034 已应用本机主实例并核对摘要，后续不可修改。
- 范围：迁移 034；延续 [ADR-047](0047-fixed-pull-revisions.md) 的不可变 PR 代码版本。

## 决策

项目维护者启用 MFA 后，为仓库及目标分支发布不可变 CI 规则版本。规则包含 1–16 个「检查名称 + GitHub App ID」和 30–3600 秒的观察有效期，使用预期规则版本避免覆盖他人编辑。App ID 标识检查来源；维护者仍须核验该 App 的工作流和凭据配置。规则本身不证明工作流内容、分支保护或评审通过。

任务负责人或有权操作该任务的维护者显式申请读取。请求固定任务/成员授权版本、仓库关联及安装、已归属 PR、代码 revision 的 head/base/ref、manifest/diff hash 与规则版本；刷新页面只读本地记录。幂等键与原始请求保持一致，丢失 HTTP 响应后重试原操作，不生成重复远端读取。同一 revision 只允许一个排队或运行中的读取，项目最多 20 个待处理请求。

Git broker 第十个处理器仍与其他 Git 处理器共享两个执行名额。每项作业由独立数据库连接、随机 claim 和 session advisory lock 持有。读取前、读取中及最终事务重新核验授权；取消、成员/任务/安装/关联/规则变化都会阻止发布。SQL 连接丢失的作业转为失败，后续执行器不会重放其远端读取。最终 COMMIT 回应丢失时只恢复已持久化的结果。

## 远端证据

使用单仓库、只读 contents/pull_requests/checks installation token。核对安装和仓库身份，读取前后核对同一 PR 的准确 head/base/ref，要求 PR 仍打开且未合并。读取准确 head SHA 的 Check Runs，完整分页两遍，各最多 1000 项；总数、ID 唯一性、状态及时间字段必须合法，两遍规范化结果必须一致。远端变化或不完整结果均拒绝。无评论、review、PR 创建、push 或 merge 写入；读取结束单独撤销 token，撤销未确认则不发布。

数据库独立核对身份、版本、时间、清理证据和检查结构，并重新计算规则结论，不接受浏览器或 broker 提交的通过布尔值。每条规则必须恰好匹配一项指定 App 的检查，且状态为 completed、结论为 success。缺失、其他生产者、进行中、失败、skipped、neutral 或同名同 App 多项均不通过。保存精确证据文本、JSONB 和 SHA-256，避免 JSONB 重排后无法复算摘要。

## 当前资格与历史

成功观察只有在当前规则、固定代码来源和 TTL 仍匹配，并且没有更新的读取请求时才显示「检查符合当前 CI 规则」。更新请求一旦提交，旧成功立即失效；新请求失败或取消也不恢复旧成功。旧证据继续可见，以便共同审阅和排查。观察是一个有时效的远端快照，无法排除远端在返回之后再次变化；后续受保护合并必须重新核验。

UI 提供规则编辑、逐项结果、证据摘要、共享历史、取消及同编号恢复；不同成员看到同一持久记录。代码 revision 仍保留其单独的固定差异浏览。

## 验证与后续

集成验收覆盖准确 SHA/生产者、并发准入、幂等、读取权限隔离、错误状态、远端变化、分页、SQL 伪造证据、取消/规则变化、过期、连接持有者丢失和真实 COMMIT 回包丢失。双浏览器验收覆盖规则发布权限/CSRF、实际 HTTP 回包丢失、共享成功、更新失败使旧成功失效及桌面/390px 布局。

最终相关 Git/PR 集成回归 116/116 通过，类型检查和全量 lint 通过；升级后原双 AI 验收记录重放成功，没有再次调用模型。

所有 GitHub 交互验收使用生成凭据的回环协议服务，不代表真实外部账户验收。签名 webhook、远端按版本人工评审、受保护合并及外部团队验收另行实现；本功能不授予合并权限。
