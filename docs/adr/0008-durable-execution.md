# ADR-008: Durable run admission and independently leased executors

Date: 2026-09-23. Status: native execution foundation implemented and locally verified; full model-backed multi-agent acceptance remains incomplete.

A browser creates a task-scoped command with an idempotency key, expected task version, broker repository ID, exact base SHA and prompt. PostgreSQL accepts the command, a new run, a fresh workspace identity, audit and outbox event in one transaction. Repeating the same key and payload returns the original command, including after the task version advances; changing the payload rejects the replay. Only one nonterminal run may own a task. Different tasks remain independently runnable.

Each run gets an independent clone, Git metadata, HOME, Pi profile and session directory. New attempts never reuse an existing workspace directory. The repository registry contains immutable broker IDs and base SHAs rather than browser-supplied host paths. A local administrator CLI imports a selected repository into a broker cache without credentials, remotes, shared object hardlinks or checkout hooks. Import is explicitly a trusted local administration action; GitHub integration and repository lifecycle UI are still pending.

The web role can submit or stop authorized commands and read project-scoped state. It cannot dispatch runs or alter terminal statuses. A separate non-superuser/non-BYPASSRLS executor role has only narrow security-definer RPCs. It cannot directly read auth tables, run tables or database administrator credentials. Pi subprocesses receive none of these database connections. Native processes sharing an OS user are still trusted-local execution, not a hostile-code sandbox.

Claiming a queued run atomically allocates a monotonically increasing workspace epoch and a 30-second lease. The supervisor renews it every 5 seconds and stops on loss of authoritative connectivity. Default admission limits are eight active writers per project and two per user; a short scheduler transaction lock protects counters, and run execution stays parallel. Selection prefers members with fewer active runs, then older queued work. These initial limits are not yet a configurable scheduler or a model cost budget. Strict dependencies currently wait for upstream task completion; consuming immutable published candidates/contracts is a later M2 change.

Every heartbeat, state transition, output batch and terminal write validates executor identity, run epoch, workspace epoch and lease expiry. Organization membership updates increment the authorization version, cancel queued work and request active work to stop. New output is rejected after revocation, even before the supervisor has finished terminating the process. Normal browser disconnects do not revoke a run. Project member lifecycle and its revocation hooks remain to be completed.

A prompt RPC response only acknowledges admission. The default driver waits for Pi's `agent_settled` event; intermediate `agent_end` or retry events cannot mark completion. Database output persists only bounded visible text/tool results and excludes system messages, private thinking and raw session paths. Batches apply stdout backpressure. Completion does not mean CI passed or a change is mergeable.

The supervisor confirms ordinary process-group shutdown before recording cancellation or releasing an otherwise completed workspace. Native process groups cannot contain a deliberately daemonized hostile process, which remains outside this profile's guarantee. RPC timeouts, uncertain process exits and expired leases enter `reconciling`; the workspace is quarantined, its epoch advances, and commands retain `unknown`. There is no automatic replay of potentially executed tools. A lost terminal database response is reconciled by reading durable state rather than invoking the tool again. [ADR-011](0011-native-run-recovery.md) adds native exit-evidence reconciliation and logical archival. Quarantined tasks stay blocked when evidence is missing; native code snapshot continuation is covered by [ADR-012](0012-workspace-snapshots.md).

Outbox sequence allocation locks the project row in the same transaction as the state change. This orders commit visibility as well as IDs, preventing a reconnect cursor from skipping an earlier uncommitted event. SSE and JSON replay use these persisted events, enforce project access on each read and recheck the session during streaming. A missing/out-of-range cursor falls back to an authorized run snapshot. Streams use bounded buffering; event retention/compaction and large-project snapshot pagination are still pending.

Local evidence includes 100 concurrent duplicate starts producing one run; competing executor claims; quota races; wrong-owner/old-epoch rejection; replay payload conflicts; revocation; delayed-commit cursor ordering; two actual Pi processes executing overlapping diagnostic tools in different clones; real descendant shutdown; lost terminal responses; and RPC timeout quarantine. Browser contexts verify authenticated API admission, CSRF/control scope, SSE live delivery/reconnect and revoked-stream closure. The browser state-machine fixture is explicitly not a model run, and the Pi tests execute diagnostic RPC tools. No claim of model intelligence or three-agent semantic coordination is made by these tests.

Next: connect the controlled model gateway, persistent run/output UI, project membership lifecycle, proven reconciliation/resume, immutable dependency outputs, intentions/contracts, resource brokering, integration candidates and the remainder of the development plan. Docker parity and hostile-code containment need their own implementation review and real container tests.
