# 讨论、固定代码建议与站内通知

F3 基础实现，2026-09-23。普通成员讨论与「任务协作说明」分开：讨论不会进入 AI 的协调上下文，也不会自动发送 steer/follow-up。

## 操作流程

1. 在任务的「讨论与代码建议」发起话题，选择要提及的项目成员。维护者、开发者、评审者可以发言；观察者可阅读和订阅。
2. 被提及者在工作台「收件箱」打开原任务和讨论，回复并保留作者、时间与成员引用。任务负责人默认订阅，其他成员显式订阅；取消订阅不屏蔽明确提及。
3. 作者、任务负责人或维护者可解决/重开讨论；旧版本不能覆盖新状态。已解决讨论需重开后才能回复或采纳。
4. 引用代码前，先保存任务交接快照。选择快照、文件、起止行，可以单纯评论，也可以附带替换文本。建议以完整行替换，空文本表示删除，末尾换行由用户保留。
5. 负责人或维护者点击「在新工作区采纳建议…」，页面填入固定快照及建议；核对模型与任务指令后点击「启动 AI」。这一步明确创建一次新的运行，会按所选模型的正常规则使用额度。
6. 执行器校验快照清单、原文件 hash、行范围和新工作区原始字节，在 Pi 启动前应用建议。应用结果 hash 和运行记录显示在讨论中；运行结束/失败/待对账也通知发起人及订阅者。应用成功不等于 AI 完成、测试通过或代码合并。

## 数据与写入边界

迁移 038 新建讨论、消息、订阅、收件箱、幂等请求和运行建议记录。001–038 已用于主实例，不可改写。

代码锚点保存 snapshotId、manifestHash、path、fileHash 和原始行范围。建议正文发布后不可变，修改建议需创建新讨论。历史版本保持原位置，不自动映射到新代码。替换建议支持同任务快照中的文本文件；迁移 063 已加入 PR／整合固定差异的行内评论，详见 [行内讨论](inline-discussions.zh-CN.md)。

只在运行前、新创建且尚无 Pi 写入者的恢复工作区应用一次。Web 没有任意路径写入接口；不会改动旧运行、原工作目录、默认分支或其他人的 AI 工作区。执行器重新验证原始字节；非法路径、符号链接、秘密内容、超限/非文本文件或旧内容不匹配会拒绝启动，原目录保留。新结果通过已有快照、验证、成果与整合流程交付。

所有读取按当前项目权限过滤，收件箱还绑定收件人；撤销成员权限后旧通知也不可读。成员提及按 ID 验证当前成员资格，不解析自由文本为身份。通知在源事务内生成，幂等提交不会重复发送；无邮件/Slack 或外部通知。

## 显式交给 AI

当前运行的控制者可以选取评论、预览并确认交给 AI，发送记录固定作者与来源，详见 [讨论交接](discussion-context.zh-CN.md)。这与采纳代码建议相互独立；普通评论不会自动进入运行。

## 刷新、草稿与长讨论

讨论标题、正文、提及、固定快照及替换文本会保存在当前标签页的会话存储中。刷新并重新通过项目权限检查后恢复；回复分别绑定话题，切换话题不会把上一条未发送回复带到另一条讨论。固定差异讨论另按来源版本、路径、代码侧和起始行隔离，并恢复所选结束行。

提交前先保存完整请求和幂等编号。服务端已保存但响应丢失时，刷新后显示「重试同一讨论操作」，继续使用原编号及原内容，不自动再发一条。浏览器禁止存储或无法读取原编号时不发起新提交，明确显示原因。成功发送只清理对应的新讨论或回复草稿，其他话题草稿保留。

这是同一标签页内的刷新／导航恢复，使用 sessionStorage；关闭标签页或清除浏览器站点数据可能清除内容，不作为服务端备份。单个任务／行内上下文缓存限制约 512 KiB，存储不足时提示处理旧草稿。

「更多回复」加载的消息会与后续刷新合并，重复响应按消息 ID 去重；已加载页面不会每 5 秒退回前 50 条。读到末尾后，只增量获取后续消息；解决状态和权限仍按服务端刷新，撤权后隐藏已读内容。
