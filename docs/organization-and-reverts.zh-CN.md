# 团队生命周期与共享历史撤回

适用迁移 070–073。默认原生运行，Docker 为可选后端。

## 团队所有权与可恢复删除

Owner 在团队管理页的「所有权与团队生命周期」操作。接任者必须是当前启用的成员且已启用 MFA。输入完整团队名称和操作原因后转让：事务内将对方提升为 Owner，将操作者降为 Admin，撤销双方旧登录会话。项目角色不随组织所有权改变；版本变化时必须刷新后重新核对。

删除前先停止 AI、终端、预览和后台作业，并核查结果未知的操作。页面会列出阻塞项，服务端也在事务内重新检查；按钮可用不是最终授权。删除会停用成员，撤销会话、邀请及静态预览，保留代码、历史、审计和证据。

这是可恢复的逻辑删除，没有物理清除入口。执行删除的 Owner 重新登录并完成 MFA 后，可从工作台恢复入口进入；其他成员看不到恢复内容。恢复只重新启用删除者，其他成员须逐一重新授权，旧邀请和旧访问能力不会复活。

## 撤回已推进的共享变更

1. 维护者在任务页「项目 Git 整合队列」展开「撤回共享历史（创建 revert 任务）」，选择一次已成功推进的记录，核对推进前后 SHA 和当前基线，填写原因后创建任务。操作要求 MFA。
2. 打开该任务启动 AI。平台在新的私有工作区对整次推进差异作反向三方合并，生成新提交。共享分支保持原状；后续独立变更保留。不是只撤回最后的溯源提交，也不 reset 共享历史。
3. 有冲突时核对文本、二进制、删除和重命名选择。运行结束后保存快照，使用与撤回目标相符的固定验证配置；仍检查旧功能存在的配置可能正确地失败，应重新定义本次应满足的检查，而不是忽略失败。
4. 验证拒绝残留冲突标记。发布成果时填写处理说明并明确确认全部冲突选择，再创建整合、取得独立评审并显式推进。AI 自述完成和人工任务状态均不能替代这些步骤。
5. 创建后若共享基线改变，原撤回来源显示失效，排队或运行的旧授权不能继续交付。刷新来源后重新创建任务；不要直接修改旧任务的固定 SHA。

首版来源限定为平台成功推进的完整变更，不接受任意远端 SHA。恢复快照不会重复应用反向变更。发布证据保留撤回来源及固定基线，可以追查这次修改为什么出现。

## 验收范围

组织生命周期、并发版本门禁、完整差异撤回、保留后来修改、冲突、旧执行器拒领、基线变化失效、固定验证／独立评审／推进已有服务端回归。真实页面已验收空团队删除和恢复、撤回任务创建、真实 Pi 检查生成提交、失败验证禁发、正确验证和显式确认发布。Owner 转让完整双 MFA 页面、撤回成果的完整页面评审推进仍按 [收尾清单](module-closeout.zh-CN.md) 保留，不能用协议结果替代。
