# 变更证据包

任务页每个已发布成果下新增「变更证据包」。成员可查看固定代码差异、原始需求和执行器验证，并下载一份 JSON。迁移 061 只增加有项目权限检查的汇集函数；复用已有成果、快照、验证和评审记录，不建立新的批准状态，不自动执行代码或合并。

## 汇集内容

- 成果版本、发布说明、来源运行/操作者、快照清单 hash、受检 commit 和仓库基线。
- 快照捕获时的目标/验收、固定依赖及契约；当前任务内容单独保留，避免后来修改的目标冒充原验证输入。
- 从 broker 仓库的固定基线对象与校验过的快照字节生成的代码差异，包含文件模式、对象 ID、可读文件 SHA-256 和逐行变化。
- 平台执行器的验证配置、命令参数、退出码、运行环境/镜像、源码未变和进程退出确认，以及有限输出的 hash。代理自述不能生成这些检查记录。
- 引用该成果的整合候选、组合验证、版本评审历史与当前评审状态；任务级讨论及该快照上的行评论/建议。
- GitHub 任务历史中的 PR 版本、各自的评审/CI/发布记录。它们不自动等同于本成果的批准，始终保留各自 head/base/diff hash。GitLab 从明确引用本成果的操作追溯其后续操作及 plan hash 评审。
- 持久可见工具事件的完成/失败计数，不复制原始工具输出、私有推理、会话 JSONL 或模型凭据。

任务级普通讨论与执行器验证分别保存；快照文件建议属于其固定 snapshot/hash。没有相关记录时对应数组为空，不生成虚假的「已经评审」。源快照继续受现有成果引用保护；证据包本身在读取时组装，不产生需要长期回收的新服务端副本。

## 状态与完整性

读取代码前后都核对项目权限和可变元数据。汇集期间有变化时返回冲突，要求重新汇集。页面约每 5 秒核对记录版本，变化后提示刷新；每次下载重新从服务器读取，不能依靠旧页面越过撤权。

`format` 为 `pi-collab-evidence/v1`。`sha256` 是 UTF-8 编码的 `JSON.stringify(payload)` 的 SHA-256，用于核对导出内容的意外变化；它不是签名，也不证明不可信文件的发布者身份。记录包含观察时间、最新成果指针、撤回、依赖与仓库基线状态。

已下载文件是历史记录，不可能主动收到后来的撤权或新版本。不能拿下载文件授权 Git 写入；应重新打开原项目查看当前状态。已有批准只适用于其中的确切 revision，原来的 Git 门禁保持权威。

## 范围与限制

复用快照/代码审阅的排除与秘密模式检测。二进制、超过 256 KiB 或 8000 行的文件只列身份与未展示原因，不能当作已核对文本；快照排除清单同时保留。可识别秘密的评论/说明等文本也被隐藏，并记录 JSON 路径。模式检测不是对任意秘密的保证，用户下载后仍须按项目共享要求管理文件。

单包最多 128 个未排除的变更文件、4 MiB 差异与 8 MiB 总 JSON；相关整合/PR/讨论也有明确上限。超过限制整包拒绝，保留原单项证据入口，不静默截断后称为完整包。没有复制外部 CI 日志全文、测试原始输出、数据库状态或运行环境镜像层。

## 验收方式

专项以实际 Pi 工具生成代码、真实快照及固定命令验证为来源，检查 diff、命令/退出码、内容 hash、评论脱敏、撤回/撤权；工具汇总使用标明为 fixture 的持久事件，不冒充模型推理。整合专项核对实际独立评审与包内版本记录一致。双成员网页检查展开代码、下载 JSON、重新计算 hash，以及撤回后的状态提示。外部 PR/CI 内容仅汇集已有数据库记录，不在下载时访问远端或执行外部写入。
