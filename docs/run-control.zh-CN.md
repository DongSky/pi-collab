# AI 会话控制与交接

在项目中打开任务，选择正在运行的 AI，在「会话控制与交接」查看当前控制者。项目全景也显示控制者。交接不创建第二个 AI，不替换工作区，不改写原运行发起人或任务负责人。

## 成员操作

1. 开发者旁观运行，填写至少 10 个字符的接管说明并申请控制权。
2. 当前控制者同意或拒绝，申请人也可以撤回。维护者可以处理接管申请，处理人和说明会保留。
3. 同意后，新控制者可以发送「调整当前方向」（Pi steer）或「当前工作后继续」（Pi follow-up）。旧控制者的页面失去发送和普通停止权限；维护者保留紧急停止。
4. 所有成员看到共同的申请、处理结果和带实际操作者的指令记录。需要暂停时停止本次运行；后续通过任务新运行及既有快照继续。

每个请求绑定控制权版本。交接回来也不会使旧窗口的指令重新有效。交接时取消尚未投递的旧指令；Pi 已接收的指令可能继续执行，交接并不撤销已经授权的工作。

「运行已接收」表示真实 RPC 接收成功，不是任务执行完成；实际执行结果查看运行输出。投递中或结果未知时不能交接，未知指令不会重发。运行结束后关闭指令入口，未发送指令留有取消记录。

## 选入成员讨论

迁移 065 提供选取评论、预览、控制者确认发送及来源回溯，见 [讨论交接](discussion-context.zh-CN.md)。普通评论不会自动指挥 AI。

## 权限与运行边界

- 观察者和评审者只能查看。只有当前控制者可发运行指令，维护者也需先接管才能发指令。
- 初始任务指令、模型、预算和运行归属保持原记录；交接只委派同一运行的后续人类指令权限。任务负责人变更仍使用项目成员管理的独立操作。
- 原发起人及受委派控制者的权限都须有效。控制者被撤权后，后续模型访问被拒绝，执行器通过现有心跳停止运行；恢复成员身份不会恢复旧控制授权。
- 指令只通过持久队列交给已持有运行租约的执行器。Web 无法发送任意 Pi RPC，不能藉此修改模型、加载插件、启动额外进程或取得其他工作区权限。
- 共享人工终端和人工编辑/AI 写入切换已由迁移 049/050/055 接通，见 [共享人工终端](shared-terminal.zh-CN.md)。讨论选入上下文仅适用于 AI，不进入终端输入。

## 开发验证与升级

迁移 `037-run-control.sql` 增加控制者、申请和指令记录；控制记录独立于 `runs.requested_by`。升级执行器前排空活动运行，再应用迁移和正常重启原生服务。已应用迁移不能改写。

- `tsx --test tests/collab/run-control.test.ts` 验证申请/交接、版本、撤权、独立运行和共享记录。
- `tsx --test tests/collab/gateway.test.ts` 的 live control 用例启动真实 Pi 进程，使用本机协议模型服务，检查交接后 steer 与 follow-up 确实进入第二次模型请求。不会调用付费模型。
- `PI_COLLAB_E2E_FOCUS=run-control npm run test:collab:identity:e2e` 使用隔离数据库和两个浏览器验证交接主流程、页面权限与窄屏布局；浏览器运行状态由协议 fixture 提供，不冒充外部模型验收。
