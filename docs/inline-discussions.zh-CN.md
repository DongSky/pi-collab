# PR 与整合差异中的行内讨论

迁移 063 为既有任务讨论增加固定差异锚点。支持 GitHub 固定 PR 版本，以及项目整合结果的文本差异；复用已有回复、站内提及、订阅、解决／重开和成员权限。评论不会自动发送给 AI，也不构成合并批准。

## 使用

1. 在任务页打开「查看固定 PR 代码差异」或整合记录的「查看固定代码差异与冲突」，读取文件列表并选择文本文件。
2. 点击差异旧侧或新侧的行号，打开「讨论所选代码」。可设置结束行；整合来源有多个任务时，选择讨论所属的来源任务。
3. 展开「发起讨论」，填写标题、正文和提及成员后发布。另一位成员打开相同固定文件即可阅读、回复；作者、任务负责人或维护者可解决／重开。
4. 讨论也出现在关联任务的普通讨论列表。站内通知仍能定位到原任务和话题。「核对评论的固定代码」重新验证权限及保存的代码，返回原侧文本和该来源是否仍有效。

讨论草稿支持同一浏览器标签页刷新恢复，按账户、任务、固定来源和行侧隔离；发送结果未知时保留原请求编号。详见 [讨论恢复](discussions.zh-CN.md#刷新草稿与长讨论)。

## 版本及权限

锚点固定来源类型、来源 ID、来源证据 hash、差异 hash、路径、旧／新侧和行范围。服务端读取受校验的固定文件检查行范围；数据库同时检查来源归属、来源 hash、关联任务、角色及 MFA。PR 只能归属它的任务，整合只能选择其来源任务。被排除、二进制、超限或不可读内容不能建立文本行评论。

代码更新不会把旧评论搬到新的版本；失效版本仍能按原锚点核对，损坏或不可用的证据会明确失败，不回退到工作目录。整合产物被讨论引用后受保留规则保护，变更证据包也带上完整锚点。权限撤销后旧评论、通知、固定代码链接均重新拒绝访问。

普通任务讨论、原有快照建议和运行前应用流程保留。此入口只评论固定差异；可执行替换建议仍使用快照建议，不能从 PR 或整合评论直接修改工作区。跨版本自动映射、批量补丁、GitLab MR 行内讨论和冲突三侧专用评论入口仍是后续增强。

## 验证

- 真实 Git／数据库专项覆盖 PR 和整合来源、精确行侧、范围与 hash 拒绝、无关任务拒绝、幂等、提及、回复／解决、失效来源保留、撤权、代码损坏及整合保留保护；变更证据包保留锚点。
- 原有 4 项讨论与真实 Pi 快照建议测试通过。
- 双成员浏览器验收入口：`PI_COLLAB_E2E_FOCUS=pull-release npm run test:collab:identity:e2e` 和 `PI_COLLAB_E2E_FOCUS=inline-integration npm run test:collab:identity:e2e`。使用隔离数据库／源码目录、本地 Git 协议和真实 Pi 工具，不调用外部模型或写入外部 Git 服务。
