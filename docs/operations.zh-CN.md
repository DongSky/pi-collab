# 原生历史导入与运维流程

本页描述已实现的 F7 原生基础。默认使用本机 Node、Git 和自动管理的 PostgreSQL，**不依赖 Docker**。开发启动器绑定回环地址并使用本机邮件箱；[团队部署入口](deployment.zh-CN.md) 已支持独立生产启动、HTTPS/预览来源及 SMTP 配置。生产产物、公网 HTTPS、真实 SMTP 投递、跨主机灾备和 Docker 持久目录仍需独立交付验收。

## 个人历史入口

项目工作台 → **个人历史** → 选择自己的 Pi `.jsonl` 会话文件。文件在浏览器内解析，按文件顺序显示用户/助手的文字，可能包含多个历史分支；默认没有选中任何消息。展开、勾选、编辑文字后确认导入。工具输出、系统消息、思考、图片、源目录、源 session 标头均不上传；文字自身可能含秘密，提交前必须人工核对。

默认仅导入者可见。选择项目共享时，该项目当前及未来有权限的成员可查阅。记录标明导入者及历史身份未核验；不会将历史行为归到导入者，也不会自动向 AI 发送任何历史指令。相同标题/文字/可见范围的重试返回原记录。导入者可删除，审计只记录标识、条数和共享状态。失去项目访问权后无法继续读取。

文字迁移限额：源文件 5 MiB、候选 1000 条、一次选择 200 条/10 万字符；列表展示最近 100 条。

### 完整来源与分支归档

同页新增「完整会话归档」。一次选择最多 20 个自己的 `.jsonl` 文件，单个最多 5 MiB、合计最多 10 MiB、每个会话最多 5000 个条目。归档前可展开源文件，核对完整内容和共享范围；默认仅自己。完整归档会保留系统内容、工具记录、思考、图片数据、源路径及其他元数据，选择此方式意味着这些内容一并存储，不适合只想迁移部分对话的情况。

支持 Pi v1/v2/v3。v2/v3 原始 ID/parentId 关系用于分支选择与路径浏览；v1 原本没有条目 ID，仅按原行号展示线性历史，导出不补写 ID。fork 的 parentSession 保留原文，同组文件名匹配时显示声明的父文件；父文件未选择则明确提示。不会读取标头里的本机路径，也不据此声称历史身份或来源已认证。

保存后可选择会话、切换分支、查看全部类型的原始条目、导出当前原始 JSONL。导出保持 UTF-8 字节（包括 BOM、CRLF 和空行），提供文件 SHA-256；不会迁移、改写或重新编号原文件。内容仅以文本和 JSON 展示，系统指令、工具调用、图片和自定义扩展不执行；压缩/context_edit 保留为历史事件，不重放模型上下文。完整归档不自动恢复活动进程或工作区，导出的文件可交给本人的 Pi 环境另行检查。

权限与文字迁移相同：开发者/维护者启用 MFA 后导入；仅本人可删除；共享文件仅项目有效成员可读，下载时重新验证权限。相同文件组与可见范围的重复上传返回原记录。每位成员每项目最多 50 组或 100 MiB，项目总额 1 GiB；删除释放额度，操作审计不包含原始内容。归档在 PostgreSQL 中保存，纳入既有加密冷备份。

## 独立安装与配置检查

使用独立代码目录、独立 `PI_COLLAB_DATA_DIR`，不要把生产数据和开发实例混用。Node 最低版本以 package.json 为准；执行 `npm ci` 后：

```bash
npm run ops:upgrade
npm run ops:check
npm run dev:local
```

首次安装会生成私有配置，初始化数据库并应用迁移。启动默认 Web 30142、网关 30143；数据库端口和 Web 端口保存在数据目录的 `config.json`。多个独立实例需要在首次启动前配置不同端口。Web 首次初始化与账户/MFA 流程沿用现有引导页面。

`ops:check` 是离线检查：须停止全部服务，检查配置权限、Node/Git、PostgreSQL 可启动、应用迁移哈希及活动/未知工作。它不会打印连接密码或密钥，不代表公网部署、安全沙箱或 SMTP 已验证。Docker 模式另检查镜像是否存在；镜像存在不代表业务对等验收通过。

## 排空与停止

```bash
npm run ops:drain -- --reason '为计划中的本机升级排空所有活动工作'
npm run ops:status
npm run ops:stop
```

排空状态持久化到数据库；页面显示横幅，拒绝新的修改，保留查看、停止和异常核查。数据库门禁与排空操作共用锁，使已进入事务的作业提交先完成；新 AI、快照、验证、整合和 Git 作业无法入队。已有作业及其资源操作可完成。运维状态只输出各类剩余数量，不输出任务正文、密钥或数据库地址。

`ready: true` 才能停止。隔离工作区、未知 Git/资源结果继续算未排空，须通过原核查流程处理；不会强行释放占用。`ops:stop` 核对启动器的 PID、启动目录与本机启动标识后发送 SIGTERM。旧版本启动器没有 supervisor 记录时，先按原终端正常退出，禁止猜 PID 批量杀进程。等全部服务退出再备份；单独启动的数据库/worker 也必须停止。

## 加密冷备份

```bash
npm run ops:keygen -- --key /private/backup-keys/pi-collab.key
npm run ops:backup -- --file /private/backups/before-upgrade.pcb --key /private/backup-keys/pi-collab.key
```

密钥为新建的 0600、32 字节文件；放在数据目录外，单独离线保管。命令拒绝覆盖已有密钥/备份。备份取得与标准启动器相同的目录操作锁，独立启动数据库核对排空和其他连接，然后干净停库，再打包整个数据目录。未确认停止的运行凭据或存活数据库会阻止操作。

数据库、Git 数据、工作区、快照、私有配置及本机模型/资源/Git 主密钥共同用 AES-256-GCM 加密。归档不跟随符号链接，不收录 socket；备份头记录原绝对路径、代码提交/脏状态、平台、架构、Node、PostgreSQL 和迁移哈希，无密钥正文。头也参与认证。外置密钥配置需独立备份流程，当前命令拒绝将其假称为完整本机备份。

这是停机物理备份；恢复须使用相同平台/架构、PostgreSQL 大版本和原绝对数据路径。它不承诺跨平台迁移，也不备份数据库以外的外部服务。备份文件和备份密钥缺一不可；仅复制数据库无法恢复加密凭据。

## 升级与回滚

1. 排空、正常停止、生成并保管完整备份。
2. 在代码目录切换到经过检查的目标版本，安装锁定依赖。运维命令不会自行 `git reset`、拉取或发布代码。
3. 执行 `npm run ops:upgrade`：仅添加新迁移；已应用迁移哈希变动或当前代码缺少旧迁移时拒绝操作。
4. 执行 `npm run ops:check`，启动 `npm run dev:local`，读取项目页面/API 做冒烟。
5. 确认后执行 `npm run ops:resume -- --reason '已完成本机升级检查与网页冒烟，恢复接受工作'`。

空目标恢复：

```bash
npm run ops:restore -- --file /private/backups/before-upgrade.pcb --key /private/backup-keys/pi-collab.key
```

保留现有目录并回滚数据：

```bash
npm run ops:rollback -- --file /private/backups/before-upgrade.pcb --key /private/backup-keys/pi-collab.key --retain-current
```

恢复先在私有暂存目录完成解密认证与安全解包，再检查数据库版本和迁移兼容性。默认拒绝覆盖已有目标。回滚须停止全部服务；现有目录保留为 `.retained-时间戳`，不会删除，随后把验证过的备份发布到原路径。保留目录含秘密，应保持私有。备份通常保留排空状态，恢复不会自动开放新作业。

回滚代码与恢复数据是两步。输出的 `backupCode` 用来寻找对应版本；若 `backupCodeWasDirty` 为真，还需自行保管当时的未提交代码。恢复旧数据后，可选择匹配代码，或用较新代码再次前滚迁移；不能把只退代码称为数据库回滚。备份后的新增工作保留在旧目录中，需要人工决策如何迁移，不能无声覆盖。
