# AI 提问、等待与成员回答

迁移 067 接通真实的“运行等待输入”流程。AI 使用 `collab_ask_user` 提出继续工作所需的问题，可以附带最多 6 个建议选项。问题先持久保存，再将运行标为 `waiting_input`；发起人与当前控制者收到既有站内通知。任务的“会话控制与交接”下可查看问题，刷新页面后仍存在。

只有当前有效控制者能回答。成员可点选建议后编辑，也可自由输入；旁观者可看问题和回答，但不能提交。需要另一位成员作决定时，沿用控制申请/交接，新控制者直接回答原问题，旧页面提交会被拒绝。回答保存实际作者、控制版本与时间，进入项目审计；它是任务输入，不替代权限变更、Git 评审或合并批准。

## 同一运行继续

提问工具在同一 Pi 进程内等待，以原编号每 2 秒读取问题状态。等待不启动新的模型请求、不创建新工作区。收到回答后，原工具调用返回回答和成员身份，Pi 才继续下一轮模型请求。网络错误、服务暂不可用或限流时继续沿用原问题编号，不自动创建第二个问题。

每次读写仍检查运行租约、执行器 epoch 和现有成员授权。同一运行最多一个待回答问题、总共最多 50 个问题；题目最多 4,000 字符、选项每项 200 字符、回答最多 10,000 字符。创建重放、回答重放、控制版本和并发提交均在数据库内约束。回答响应丢失时可重试同一回答；刷新后也能直接看到已经保存的回答。

等待保留工作区、并发名额、资源租约和原运行时限，不等于无限期暂停。提问前同批次已经开始的工具仍可能结束；它不是文件冻结操作。运行被停止、失败或进入核查时，待回答问题取消；原进程退出后不自动恢复提问工具。需要长时间离线交接时，仍使用停止后的快照/新工作区流程。

已保存回答显示“已回答”；这表示平台接纳，不声称 AI 已完成后续行为。后续执行以运行输出为准。其他成员讨论、AI 的普通疑问句不会自动成为这个流程，AI 必须调用提问工具。

## 接口与验证

`GET /api/collab/runs/[id]/questions` 提供当前项目可见的问题/回答历史及控制状态；`POST /api/collab/questions/[id]/answer` 接收回答、控制版本与幂等编号。数据库表 `collab.run_questions` 使用项目 RLS，客户端不能直接改写历史。

21 项控制/协调测试通过，涵盖问题去重、单次通知、交接回答、旧控制者拒绝、回答重放、停止取消、跨项目/成员权限和原协调能力。2 项扩展测试验证未知创建结果重试原编号、等待/取消和原基线上下文功能。

原生与 Docker 各运行真实 Pi、本机模型协议服务，验证第一轮模型提问后保持等待且请求数不增加；新控制者回答后恰好进行第二轮请求，模型收到回答与作者，工作区不变。另一轮验证停止待回答运行，不再调用模型。双成员浏览器验证刷新保留、通知、控制交接、选项/自由回答、响应丢失重试、旧控制者及 CSRF 拒绝，并回归原指令/讨论交接；桌面/390px 截图已检查。

测试没有外部模型推理或外部消息发送。原生为默认，Docker 加载相同扩展和协议。
