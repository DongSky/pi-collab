# 代码浏览与多人编辑工作区

日期：2026-09-25。

## 从哪里打开

- 左侧活动栏「项目代码」：浏览已连接仓库的当前基线，无需先启动 AI。文件树位于工作台左侧侧边栏；点击文件在顶部主标签栏打开独立文件标签，与任务标签共用一栏。中央仅显示当前文件编辑器，正文提供行号、JS/TS/JSX 语法高亮与文件内查找。
- 侧边栏「文件 / 任务」切换资源树与任务列表。打开任务默认进入「代码 / 共编」。浏览器的「代码来源」可以切换仓库基线与已保存任务快照。
- 快照点击「编辑此快照」，或切到「多人代码编辑器」选择已有草稿。新建文件支持 `src/example.ts` 这样的目录路径；修改每秒同步，Ctrl/⌘ S 可立即触发同步。
- 从运行取得代码：展开「查看本次运行的修改 / 准备编辑」，在运行停止后保存快照。共享草稿可保存版本、冻结并交给 AI 接续。

## 协作与范围

多人编辑沿用 Yjs 合并、在线成员和光标、本机未同步草稿恢复。切换文件前确认同步完成；已冻结或已交给 AI 的版本保持只读。仓库基线也只读；当前入口不直接编辑 Git 基线或正在运行的 AI 工作区。首次编辑需要停止后的任务快照。尚未实现语言服务器、断点调试、跨文件重构或完整 IDE 插件系统。

浏览接口按项目权限读取受管 Git 对象，只能读取数据库记录的当前基线；不接受任意目录或 Git ref。文件读取前后核对授权版本和基线，页面定期重新验证访问权限。排除敏感目录、符号链接和子模块；二进制、疑似凭据和超过 256 KiB 的正文不显示。文件树上限 10000 项，Git 输出另有 2 MiB 上限。

## 保存反馈与快捷键

每个共享文件的主标签、编辑器工具栏和底部状态栏同步显示保存状态：未保存为圆点，服务器确认后为勾号；保存中、保存失败、离线、只读均有文字提示。悬停标签可查看保存时间、服务器文件版本和本机备份情况。刷新后尚未打开的标签显示「待核对」，重新加载后再确认状态。

- Ctrl/⌘ S：立即保存并核对服务器回执，显示成功时间、文件路径与「共享草稿」位置。自动保存每秒进行；无修改的后台轮询不刷新保存时间。
- Ctrl/⌘ Shift S 或「另存为…」：输入共享草稿内的新路径，原文件保留；保存成功后打开新标签。目标已存在、路径冲突或来源被协作者改变时明确报错，不覆盖他人文件。
- 「下载副本」：发起浏览器下载，需在浏览器下载列表确认结果。它不会改变共享草稿的保存状态。只读代码按保存快捷键会说明限制。
- 协作信息显示其他在线成员、收到协作更新的时间，以及冻结、交给 AI、归档等只读原因。
- 保存失败时保留未保存标记和本机恢复副本；切换或关闭文件前必须完成同步，刷新或关闭网页有离开提醒。恢复连接后重新确认成功才移除未保存标记。

这里的「已保存」指服务器共享草稿，Git 提交与交付仍需通过任务的版本、评审和 Git 流程单独完成。

## 默认保存策略：检查最新版与三方合并

自动保存、快捷键保存和离开文件前的保存都先检查版本。浏览器持有服务器确认的基线文本、版本和签名，服务器在同一个写事务中读取最新版，再使用 `git merge-file --diff3` 比较基线、个人修改和服务器修改。不同位置的兼容修改自动合并；同一区域的重叠修改、删除/修改等冲突不会写入共享文件。Yjs 继续用于编辑状态和协作光标，但不再替代保存阶段的冲突判断。这里检测的是文本合并冲突，业务语义仍需评审。

发生冲突后，该文件自动保存暂停，标签与底部显示「保存冲突 · 待解决」。面板提供共同基线、个人和服务器 Diff，以及待保存结果相对服务器的 Diff：

1. **手动解决**：修改候选文本，也可先选用个人或服务器版本作为候选；这些选择不会立即覆盖文件。处理完冲突标记后点击「确认解决并保存」。
2. **Agent 修复**：选择项目已启用的模型，点击「让 Agent 修复」。系统创建独立修复任务，使用现有模型额度、执行与审计流程。修复任务可在新窗口查看；完成后点击「读取 Agent 候选」，首次读取可能需要等待候选快照生成。候选回填到 Diff 面板，仍需人工确认保存。
3. **再次变化**：确认保存时再次核对服务器版本；如有变化，重新展示冲突，不覆盖新修改。「重新读取最新版（保留候选）」可保留正在编辑的方案并更新对照内容。

可下载三方内容与候选，保存本机恢复副本失败时也可手动保留完整对照。未解决冲突时，切换、关闭、保存版本或交给原任务 AI 均受保存保护。本机恢复副本保留基线、冲突和正在修改的候选；旧版或无法验证基线的恢复副本需手动核对，不自动覆盖。Agent 请求在当前浏览器会话中保留请求编号，重试同一请求复用同一个修复任务和运行。候选任务基于关联仓库的当前基线提供上下文，三方文本是待修文件的权威输入；不会复制正在运行的其他工作区。三方修复指令超过现有任务的 20,000 字符限制时明确提示，需手动处理或拆分任务。

验证：合并策略、签名基线、过期保存、解决期间再次变化、旧协议拒绝、共编、本机恢复和 Agent 独立任务/幂等/候选快照共 17 项测试通过。Computer Use 实测冲突标记阻止保存；使用已授权的 所选测试模型 完成真实修复任务，读取候选后制造成员的新修改，验证再次拦截，人工合并后确认保存，所有修改保留。并发注入只用于一次性沙箱，已撤销。开发沙箱与主数据独立；主开发目录未运行生产构建。类型检查、ESLint 和独立目录生产构建通过（保留上游会话 HTML 导出的动态依赖警告）。


## 编辑器右栏直接使用 AI

打开共享草稿中的文件，右栏默认显示「当前文件 AI」。文件 AI 和任务运行均提供独立的「对话 / 设置」标签：对话页集中展示消息、运行输出、需求输入与候选 Diff；设置页放置模型，任务设置还包含运行方式、仓库、恢复来源与额度。切换标签保留草稿、输出和候选，支持左右方向键切换。输入自然语言需求、选择项目模型并发送，无需冻结、归档或离开编辑器。发送前先检查并保存当前文件；原共编草稿保持开放。右栏可查看运行输出、停止 AI、追加调整/后续指令和回答 AI 提问，也可打开完整任务。

每轮 AI 使用独立任务与工作区，沿用项目模型、额度、权限、控制权和审计。当前文件已确认版本是权威输入，仓库当前基线提供其他代码上下文；目前这个入口应用单文件候选，多文件整体交接仍使用「任务运行」的冻结交接流程。最近四条对话（每条最多 3,000 字符）用于下一轮；完整指令与文件上下文合计受任务的 20,000 字符限制。浏览器会话内保留输入草稿、请求编号、运行、候选与应用状态，刷新后可恢复，未确认请求沿用同一编号重试。

AI 完成后自动生成候选快照并在右侧显示 Diff，不自动覆盖编辑器。点击「检查最新版本并应用」会先保存本机的新修改，再以 AI 开始时的签名版本为共同基线，与服务器最新版三方合并。非重叠修改一起保留；重叠修改进入中央冲突面板，须人工修改 Diff 或请求 Agent 修复后再确认。下一轮使用当前共享文本与最近对话，继续修改上一轮候选前先检查并应用它。

本次验证（2026-09-25）：18 项相关测试、类型检查、ESLint、独立目录生产构建通过。Computer Use 在独立沙箱中使用已授权的 所选测试模型 完成两轮真实编辑，验证右栏启动、追加指令接收、输出、候选 Diff、刷新恢复与下一轮上下文。第一轮应用自动保留成员在 AI 运行期间新增的行；第二轮双方改同一行，应用被拦截并转入三方冲突面板，人工合并后保存成功。已转入合并面板的候选不可再次应用。沙箱最终处于「已保存」，生产构建没有触碰主开发目录的 `.next`。


## 打开本机工作文件夹

左侧「＋ 打开文件夹…」或右侧 AI「设置 → 打开工作文件夹…」唤起浏览器目录选择器。选择项目目录、核对导入清单与排除项，点击「导入并打开」。维护者与开发者可导入到当前项目；项目成员按原有权限访问副本。导入会创建仓库基线、任务、准备记录、快照和共享草稿，并直接打开第一个可编辑文件；无需先运行 AI。设置页显示当前文件夹名称和本轮 AI 的实际工作路径。

这是浏览器选择文件后建立的**协作副本**，不是对原目录的实时挂载。包含选择时的未提交文件内容，原目录不修改、不自动回写；本机 Git 历史、远程凭据、hooks 不导入，副本有独立 Git 基线。要保留完整 Git 来源关系，继续使用仓库接入流程。浏览器不会向服务器提供任意本机路径读取权限。页面展示排除项；服务端再次检查路径、重复/大小写冲突和疑似凭据。依赖目录、`.git`、`.env` 等不进入副本。

当前限制：一次 2,000 个文件、单文件 2 MiB、合计 32 MiB；每项目最多 64 次目录导入、累计 512 MiB，另受原有产物配额约束。空目录不导入，二进制文件可进入基线但不可在文本共编编辑器中修改；超过共编单文件 256 KiB 的文件也不能直接共编。导入同一请求可重试，不重复创建任务；重新选择目录属于新导入。

## 本地目录关联（直接回写）

侧栏「本地目录关联」可把项目绑定到服务端可访问的本机目录（绝对路径，需维护者 / 开发者权限，绑定与解绑均审计）。这是与「导入副本」并列的第二种模式：绑定后保存流程变为「共享草稿保存成功 → 自动回写本地目录」，不再要求走 Git 分支交付才能把改动送出去。

回写复用共编的三方合并逻辑（`git merge-file --diff3`）：以「上次回写版本 / 本次保存内容 / 磁盘当前内容」为基线三方合并。磁盘无变化或内容一致时直接写回；磁盘有外部修改时自动合并非重叠部分，重叠则本次不覆盖磁盘，在编辑器下方弹出回写冲突面板，可下载三方内容、在本地处理后重试，或确认用保存版本覆盖。回写永不让保存失败：磁盘失败只在通知栏说明，共享草稿已保存。

路径安全：绑定目录必须显式配置，不能由任意请求指定；每次写回校验相对路径、拒绝越界与符号链接逃逸；写入使用同目录临时文件 + rename，避免部分写入；服务端数据目录不可绑定；同一目录同一时间只属于一个项目。更换绑定目录会作废各文件的回写基线，下次保存按导入时内容重新推导。

验证：`tests/collab/local-writeback.test.ts` 8 项通过（首次回写、幂等、外部修改自动合并、重叠冲突不覆盖、删除语义、路径穿越与符号链接逃逸、强制覆盖）；`075-local-directory-binding.sql` 在真实 PostgreSQL 上应用并逐函数验证（绑定、基线记录、换绑作废、跨项目冲突、解绑、审计）；类型检查与 ESLint 通过。用户与受控 Agent 共用同一回写入口（`syncDocument`），规则一致。

## 语义编辑与批量修改

共享草稿中的 JS / TS 文件新增语义工具栏：F12 转到定义，Shift F12 查找引用，F2 重命名符号，Ctrl / ⌘ . 快速修复，Ctrl / ⌘ Shift O 文件符号。鼠标停留可查看类型，补全来自当前草稿的类型服务。“问题”显示诊断并可点击定位。其他语言仍保留现有编辑与高亮。

符号重命名、整理导入、快速修复及左侧搜索中的“预览跨文件替换”会先显示多文件 Diff，确认后整批保存。若预览后有任何草稿修改，整批操作拒绝，需重新生成预览。保存后可在预览面板撤销该批修改；撤销同样检查版本，不覆盖协作者的新修改。

“格式化”读取当前草稿内最近的 Prettier JSON / YAML 配置（含 package.json.prettier 和 overrides），回执会显示来源。可执行配置与第三方插件不在在线格式化进程中运行。

Ctrl / ⌘ P 快速打开当前草稿文件。文件标签可拖动排序，或聚焦标签后用 Alt Shift 方向键排序。“编辑器偏好”保存当前浏览器的字号、缩进和折行设置。语言、依赖类型、批量规模和未完成能力的边界详见 [单人开发核查](./solo-development-audit.zh-CN.md)。
