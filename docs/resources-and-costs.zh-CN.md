# 资源、并发与费用

F5 基础范围，2026-09-24。项目页「资源与费用」集中展示并发、模型价格、每日用量及工作区测试环境。默认原生运行；Docker 的同等执行流程在 F7 单独验收。

## 调度与预算

维护者启用 MFA 后可以调整项目同时运行的 AI 数（1–32）、每人在本项目同时运行的 AI 数（1–16）、每日 token 上限，以及可选的每日 USD 预算。默认并发是项目 8、每人 2；用户上限现在明确按项目计算，不是跨项目的账户总上限。修改有版本检查、幂等记录和项目审计。

调低并发不会强停已活动的 AI，新的运行等待空位。界面显示成员的活动/排队数及是否在等待并发名额；依赖、执行器和资源租约仍使用已有等待机制。停止中或待对账的 AI 仍占名额，不能通过刷新页面绕过。

价格由维护者填写 USD/百万输入及输出 tokens，并记录价格来源。每次发布是新的不可变版本；请求预留使用当时价格，结算不使用后来修改的价格。预算是本平台估算上限，不是提供商账单或支付功能；目前缓存输入按普通输入价估算，暂不计算折扣、汇率、税款或提供商额外费用。

网关在同一数据库事务里预留 token 与金额，防止多个 AI 同时超额。成功响应按可核对的 input/output 用量结算；断线、结果未知或越过预留边界时保留整个预留。旧请求价格缺失保持未知，不追溯编造价格。

用量按 UTC 日期计入请求发起日，显示已知用量估算、正在预留、结果未知的保留额、价格未知请求数及最近请求。启用金额预算后，模型未定价或当天已有无法定价的历史请求会拒绝新模型调用；管理员需要核对情况，不能把未知计为零。取消金额上限需要明确保存设置，token 限额继续有效。

## 工作区测试环境

每次运行取得执行名额后自动分配独立 PostgreSQL 测试 schema 与本实例唯一端口（41000–60999）。资源服务创建专用数据库角色，密码仅供 broker 使用。AI 从 `collab_get_context.resources.environment` 读取资源 ID，通过已有申请/执行/释放工具执行 SQL。它不能申请另一个工作区的私有资源；手工创建的共享数据库资源仍走原有租约机制。

这里的「测试库」是同一 PostgreSQL 实例中的隔离 schema，不是独立 PostgreSQL 服务或生产数据库。应用直接使用 DATABASE_URL、独立数据库扩展/版本等环境属于后续部署模板能力，当前不向 AI 发放原始数据库密码。

原生 Pi 进程取得 PORT、PI_COLLAB_PORT 和 HOST=127.0.0.1。启动时检查分配端口是否已被其他本机进程使用；遇到占用不会启动 AI。端口名额在本实例内互斥，但不是操作系统网络隔离，也不能约束未受管理的程序在之后抢占端口。项目服务需使用分配的 PORT；分配不自动启动服务或发布预览。Docker 的端口及网络隔离与 F7/F8 一起验收。

维护者可明确确认删除测试数据后，重置空闲测试库，或回收已经确认停止的工作区测试库和端口。存在数据库租约、排队/未确认退出的 SQL 作业时拒绝操作；隔离中的工作区不能强制回收。重置递增版本及资源 epoch，旧租约不再有效，服务清除 schema 和旧角色后重新创建空库。操作记录与历史 SQL 证据保留。

确认停止满 24 小时后自动清理 scratch 测试数据并释放端口。无法确认停止的工作区不会因超时而被复用。代码快照不包含测试库数据；需要保留的测试结果应先保存为项目文件或其他持久证据。

## 验收与后续

主要流程使用隔离数据库、真实 PostgreSQL 查询、真实本机 Pi 及回环模型协议验证，不额外调用外部模型。费用、并发及资源生命周期有 API 和权限测试，双成员网页验证维护者配置、成员共享状态、资源重置/回收及移动布局。

长期资源保留策略配置、按用户的独立金额钱包、多币种、缓存折扣与账单对账、外部服务模板及大量工作区负载在统一增强/验收队列中，基础交付不表示这些已完成。

主实例升级 041/042；51 项相关回归通过，最终资源/原生 Pi 端口专项 2 项通过。双成员网页实际执行配置、重置及回收，截图见 test-results/collab/capacity-{desktop,mobile}.png；类型检查与 lint 通过。


## 运行时长与工作区磁盘

资源与费用页的「运行时长与磁盘额度」提供项目策略、成员/项目工作区总额度和最近 100 个工作区用量。维护者且启用 MFA 才能更改，版本冲突拒绝覆盖、重试幂等，修改有审计。AI 默认 1800 秒，人工终端 14400 秒；每工作区 2 GiB、每位成员 20 GiB、项目 100 GiB。每次领取任务时固定时长及工作区额度；调整策略不延长或缩短已启动的运行。

启动前按整份工作区额度预留，项目或成员空间不足则保留排队。工作区包含 Git checkout、私有 HOME 和 Pi 会话目录，按逻辑文件大小计数，不跟随符号链接。执行器约每 2 秒测量，超过固定额度就停止写入进程并保留文件；完成前再次测量。约束是可观察的软配额：快速写入可能在检测间隔内超额，不能代替文件系统硬配额或恶意代码隔离。

已停止/归档目录继续占额度，完整测量成功后按实际大小计入；未知用量保守保留预留并阻止同项目新启动。常驻执行器周期测量已停止工作区；当前没有「删除代码来腾出名额」的自动操作。工作区列表区分测得值与用于准入的额度值，不展示文件名或内容。超额/超时原因也出现在运行页。

范围边界：当前额度只覆盖已登记任务工作区；仓库镜像、快照、验证/整合副本和其他产物的整体存储治理仍需完成。不会把工作区软配额标成全实例磁盘限额。
