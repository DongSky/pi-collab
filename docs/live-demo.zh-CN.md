# 双用户、双真实模型本机验收

本流程使用原生版本，不需要 Docker。模型由本机 Pi 配置的 `所选测试模型` 提供，调用会消耗该供应商额度。验收通过正式应用 API、运行队列、Pi 进程、模型网关及后台执行器，不使用伪造模型响应或测试 worker 生成代码。

## 准备与执行

1. 运行 `npm run dev:local`；若 30142/30143 已有健康服务，直接复用。
2. 运行 `npm run demo:live:prepare`，创建独立演示组织、Alice/Bob/Reviewer 账号、练习仓库、任务、固定测试配置和独立评审规则。该开发配置流程与 `dev:seed` 一样使用受信本地管理权限，不代替生产邀请/MFA 验收。
3. 明确选择模型后运行 `npm run demo:live:model -- --from-pi --provider PROVIDER_NAME --model MODEL_ID`，将占位符替换为本机 Pi 中已配置的供应商和模型。此命令仅导入所选模型的当前静态配置，凭据加密保存。重复运行会核对现有配置；有变化时创建新 profile 并保留旧运行的历史。它不是完整的生产密钥轮换功能。
4. 运行 `npm run demo:live:run`。两个独立浏览器分别登录 Alice 和 Bob，通过任务界面启动真实 AI。脚本核对运行时间重叠、Bob 无权停止 Alice、Reviewer 无权启动 AI。
5. 两个运行均完成后，运行 `npm run demo:live:accept`。检查文件边界，冻结快照，执行单任务验证，发布成果，组合代码并运行全部检查，由独立测试账号评审，通过正式账号 API 为演示维护者启用 MFA，再推进本地练习仓库的受管理 Git 基线。验证码密钥/恢复码仅保存在同一私有状态文件，后续登录验证 MFA。

脚本输出运行与验收 ID，不输出账号密码或供应商密钥。账号仅存于私有 `.local/live-demo/state.json`，不要提交、截图或共享这个文件。成功报告为 `test-results/collab/live-acceptance.json`，截图为同目录 `live-*.png`。

## 中断与重试

各演示命令共用本地目录锁，防止并发覆盖状态。脚本在发送变更请求前持久化幂等键和请求内容；中断后用相同命令恢复已有操作，避免重复启动或发布。只有之前两个运行均明确失败/取消，才使用 `npm run demo:live:run -- --retry-failed` 创建新的一对。已成功、仍运行或状态未知的作业不得按失败重开；已完成验收的演示也不会隐式重置。

供应商 429、认证失败及服务故障显示为不同原因，网关不隐式重放已接纳请求。不确定的计费保留额度，不以“失败”自动退款。Pi 凭据变化后需显式重新运行模型导入；刷新浏览器不会替换项目凭据。

## 验收边界

- Alice 只实现 `pricing.mjs`，Bob 只实现 `shipping.mjs`。两个工作区来自同一基线，各自验证通过不等于组合通过。
- 固定测试覆盖输入验证、折扣舍入、运费和最终订单总价；测试本身不可由 AI 改写。
- 原始练习仓库保持不变。推进的是平台受管理的本地仓库，并保留来源成果、检查及评审版本。
- Reviewer 是自动化生成的独立账号，用来验证权限与流程，不代表真人审批。
- 此演示验证原生双模型开发闭环，不证明 Docker 对等、远程 GitHub 交付、生产部署或所有计划功能已经完成。
