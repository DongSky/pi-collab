## 验收规则与当前环境

每个模块按设计条款、实现核对、缺口修复、服务端回归、双账户实际页面操作的顺序收尾。成功流程与相邻权限/失效流程都要检查。代码检查、直接 API 测试、既有自动浏览器记录和本轮 Computer Use 分开记，不互相替代。

本轮使用独立源码副本、临时数据库及 Safari 普通/私密窗口分别登录 Owner 和 Developer。主实例的数据与服务保持运行。早期手动沙箱沿用了同主机默认 cookie 名，可能覆盖主实例的浏览器登录状态；已修复新沙箱的 cookie 命名空间与认证密钥隔离，旧沙箱未重启，不将其追记为已隔离。手动启动命令为 `npm run test:collab:identity:e2e -- --manual`，退出只清理该临时环境。

Mac 已解锁，本轮继续使用原生 Computer Use 操作 Safari 普通／私密窗口。页面验收使用一次性测试账户、仓库和数据库；真实模型仅使用已授权的 所选测试模型。这里的“待点验”仍表示未完成，不以旧阶段的自动浏览器记录替代。

## 输出过滤边界

新增过滤覆盖已识别的 Provider/GitHub/AWS token 前缀、Bearer、数据库连接串、常见凭据字段及 PEM 起始段。敏感行保守隐藏到换行；PEM 隐藏到密钥结束标记；超过 256 字符的连续 ASCII token 隐藏，避免无限缓存。普通输出最多延迟到一个 token 的边界，不按计时器提前释放；中断时的未完成 token 不释放原文。最终完整消息与错误摘要采用同一规则。

该规则用于减少日志的意外泄露，不能识别任意无标记秘密，也不宣称抵御恶意项目编码/混淆后的外传。它不替代进程权限隔离，不回写清洗历史数据库记录；人为填写的任务、讨论及终端输入另有数据可见性。需要在后续秘密管理复核中保留这些边界，不能把“已补可见输出过滤”写成“所有秘密管理验收通过”。
